# WML 스크리너 (GitHub Actions)

오닐·미너비니·리버모어의 공통 원칙(WML 프레임)을 코스피·코스닥 보통주 전 종목에 적용해, 장 마감 봇과 모닝 봇이 읽을 결과 파일을 만듭니다.

```
[장 마감 봇 16:05] ──workflow_dispatch──▶ [wml-screener.yml]
                                           ├ 한국투자증권 Open API: 지수·종목 일봉(수정주가)·위험 플래그
                                           ├ 지표 계산: 추세 템플릿 8항목, RS 순위, 베이스/VCP·피벗, 돌파, 분산일·FTD
                                           └ wml-data 브랜치에 커밋: wml/latest.json · latest.md · metrics.csv · archive/
[장 마감 봇] ◀── wml/latest.json 읽기 ── 해석·검증·촉매 보강 → 노션 → 카톡
[모닝 봇 08:10] ◀── 같은 파일(전일 결과) ── 밤사이 변수로 재확인
```

## 1. 설치 (최초 1회)

1. **한국투자증권 Open API 신청**: 한국투자증권 계좌 → KIS Developers(apiportal.koreainvestment.com) → API 신청 → APP KEY / APP SECRET 발급. 시세 조회만 쓰고 주문 기능은 코드에 없습니다. 모의투자 키로도 시세 조회는 되지만 초당 호출 한도가 낮아 느립니다.
2. **파일 추가**: 이 폴더(`scripts/wml/`)와 `.github/workflows/wml-screener.yml`을 저장소 main 브랜치에 커밋합니다.
3. **GitHub Secrets** (Settings → Secrets and variables → Actions → Secrets)
   - `KIS_APP_KEY`, `KIS_APP_SECRET`
4. **GitHub Variables** (같은 화면의 Variables 탭, 선택)
   - `KIS_PAPER` = `true` (모의투자 키를 쓸 때만)
   - `KIS_RPS` = 초당 호출 수 (기본: 실전 15, 모의 4. `EGW00201` 오류가 잦으면 낮추세요)
5. **시험 실행**: Actions → WML Screener → Run workflow → `limit`에 `50` 입력. 성공하면 `wml-data` 브랜치에 `wml/latest.md`가 생깁니다. 내용을 확인한 뒤 `limit` `0`(전체)으로 한 번 더 실행합니다. 첫 전체 실행이 가장 오래 걸리고, 이후에는 캐시로 증분 조회합니다.

## 2. 소요 시간·호출 수 [추정]

| 구분 | 호출 수 | 실전 키(15회/초) | 모의 키(4회/초) |
|---|---|---|---|
| 첫 전체 실행 (종목당 약 3회) | 약 7,000회 | 약 8~15분 | 약 30~45분 |
| 매일 증분 (종목당 1회 + 플래그 최대 150회) | 약 2,500회 | 약 3~6분 | 약 12~20분 |

종목 수는 마스터파일 기준 보통주만 셉니다(ETF·ETN·우선주·스팩·리츠 제외). 실제 시간은 실행 기록의 `elapsed_sec`으로 확인하세요.

## 3. 판정 규칙 (모두 [계산]값, 상수는 `indicators.py`의 `P`)

- **추세 템플릿(미너비니) 8항목**: ①종가 > 150·200일선 ②150일 > 200일 ③200일선 21거래일 전보다 상승 ④50일 > 150·200일 ⑤종가 > 50일 ⑥52주 저가 +30% 이상 ⑦52주 고가 -25% 이내 ⑧RS 70 이상. 데이터가 부족한 항목은 `null`(미확인)이고 통과로 세지 않습니다.
- **RS**: 0.4×3개월 + 0.2×6개월 + 0.2×9개월 + 0.2×12개월 수익률의 유니버스 내 백분위(1~99).
- **베이스**: 최근 130봉 최고가 이후 구간을 3% 지그재그로 나눠 수축폭을 잽니다. VCP = 수축 2~6회, 점점 작아짐(15% 허용), 첫 수축 35% 이하, 마지막 수축 10% 이하. 피벗 = 마지막 수축이 시작된 고점. 그 밖에 컵핸들 후보·플랫베이스·기타·깊은 조정(35% 초과, 부적격).
- **실행 후보**: 템플릿 7/8 이상 + 미확인 0개 + 베이스 적격 + 종가가 피벗 -3% ~ +5% + 당일 위험 플래그 없음 + 20일 평균 거래대금 30억 원 이상 + 시가총액 1,000억 원 이상 + 관리종목·시장경고·정리매매·거래정지·투자유의·단기과열 아님. RS 순으로 최대 10개. 시장 국면별 최대 개수(5/2/0)는 봇이 적용합니다.
- **손절 제안**: 마지막 수축 저점 1% 아래. 단 피벗 대비 -8%보다 깊으면 -8%로 제한합니다.
- **돌파**: 종가 > 피벗 + 거래량 50일 평균 1.4배 이상 + 종가가 당일 범위 상단 절반 = "돌파 성공". 조건 미달은 "약한 돌파", 장중 돌파 후 피벗 아래 마감은 "돌파 실패".
- **시장 국면(제안)**: 분산일 = -0.2% 이상 하락 + 거래량 증가, 25거래일 경과나 이후 +5% 상승 시 소멸. FTD = 상승 시도 4일차 이후 +1.25% 이상 + 거래량 증가. 200일선 아래·분산일 6개 이상·FTD 없는 조정이면 조정·하락 / 분산일 4~5개나 50일선 아래면 압박 / 그 밖은 확인된 상승추세.
- **한국 시장 보정 플래그**: 상한가(+29.5% 이상), 거래대금 20일 평균 3배 + 음봉(분배 의심), 3일 누적 +50%(단기 과열). 플래그가 있으면 실행 후보에서 빠집니다.

## 4. 결과 파일 (`wml-data` 브랜치)

- `wml/latest.json`: `status`(ok / incomplete / error), `as_of`, `is_today`, `market`(코스피·코스닥 국면), `breadth`(신고가·신저가), `new_high_sectors`, `candidates`, `watch`, `breakouts_today`, `failed`, `params`
- `wml/latest.md`: 같은 내용의 사람이 읽는 표
- `wml/metrics.csv`: 전 종목 핵심 지표 (보유 종목·전일 후보 조회용)
- `wml/archive/YYYYMMDD.json`: 날짜별 보관

봇에서 읽기: `git fetch origin wml-data && git show origin/wml-data:wml/latest.json`

## 5. 확인이 필요한 항목 (첫 실행 로그로 점검)

- 지수 일봉 API 문서의 해당 절에는 코스피 `0001`만 나와 있습니다. 코스닥 `1001`이 이 API에서 조회되지 않으면 실행이 "지수 일봉이 부족합니다"로 멈춥니다. 이때 업종코드 목록에서 코스닥 종합 코드를 확인해 `screener.py`의 `"1001"`을 바꾸세요.
- 마스터파일 속성 영역 길이(코스피 228자 확인, 코스닥은 자동 판별). 판별에 실패하면 "마스터파일 형식 판별 실패"로 멈춥니다.
- 위험 플래그의 값 체계가 필드마다 다릅니다. 코드는 `N`·`0`·`00`·빈값이 아니면 위험으로 봅니다. 정상 종목이 대량으로 빠지면 `price_flags` 원문 값을 확인하세요.
- 15:52 실행 시점의 누적 거래량에 시간외 거래가 포함되는지 확인되지 않았습니다. 돌파 거래량 비율을 해석할 때 참고하세요.
- 거래대금은 종가 × 거래량 근사치입니다.

## 6. 한계

- 베이스·VCP 판독은 규칙 기반 근사입니다. 차트 판독을 대신하지 않으니 봇이나 사람이 최종 확인합니다.
- 실적(EPS·매출) 보조 필터는 포함되지 않습니다. 봇이 DART로 보강합니다.
- 외국인·기관 수급은 포함되지 않습니다.

## 7. 테스트

```
python scripts/wml/test_indicators.py        # 지표 단위 테스트 (9개)

```
